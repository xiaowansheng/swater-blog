### 1.4 `/admin/test/useragent` 端点无认证绕过

**文件**: `blog-service/src/main/java/com/blog/modules/talk/controller/admin/UserAgentTestController.java:18-19`

控制器映射到 `@RequestMapping("/admin/test")`（非 `/api/admin/test`）。  
Sa-Token 登录拦截器仅保护 `/api/admin/**` 以及 `/api/auth/current`、`/api/auth/userinfo`、`/api/auth/refresh` 三个具体子路径。  
API 权限拦截器仅保护 `/api/**`。  
`/admin/test/useragent` 两个拦截器都不覆盖，全局 `SecurityFilter` 仅做输入消毒不做认证，端点完全无认证。

**操作**:
- 将 `@RequestMapping("/admin/test")` 改为 `@RequestMapping("/api/admin/test")`
- 或将此文件移至 `ops` 包与 `MonitoringController` 同级

### 1.6 邮件会话 HMAC 密钥默认空值（功能不可用风险）

**文件**: `blog-service/src/main/resources/application.yml:157`

```yaml
auth:
  email-session:
    secret: ${AUTH_EMAIL_SESSION_SECRET:}
```

`AUTH_EMAIL_SESSION_SECRET` 未设置时 HMAC 签名密钥为空字符串。`EmailSessionTokenUtil` 在密钥为空时采用 fail-closed 策略：`createToken()` 抛出 `IllegalStateException`，`verify()` 直接返回 false，**因此无法伪造令牌**，但邮件验证、密码重置功能会完全不可用（功能性 DoS）。

> 修正：此前版本误报为"可伪造任意邮箱验证令牌"。经核对 `EmailSessionTokenUtil.java:16-17, 30-32, 54-57`，空密钥下认证不会绕过，仅功能失效。

**操作**:
```bash
# .env 中设置
AUTH_EMAIL_SESSION_SECRET=<32位以上随机字符串>
```

### 1.7 登录密码明文写入日志数据库

**文件**: `blog-service/src/main/java/com/blog/infrastructure/aspect/LogAspect.java:213-226`

`LogAspect` 将所有方法入参 JSON 序列化后存入 `log_operation` 表的 `request_param` 字段。  
`AuthController.login()` 的 `LoginDTO` 包含 `password`（明文）与 `encryptedPassword`（RSA 加密）字段，会完整写入数据库。  
`sanitizeArgs()` 方法仅过滤了 Servlet 类型，未过滤密码/令牌字段。  
`DataMaskingService.maskPassword()` 存在但仅在 `SecurityTestController.java:84` 测试端点中调用，**未在登录/日志路径中调用**。

**操作**: 在 `sanitizeArgs()` 中对 `LoginDTO`、`ResetPasswordDTO` 等包含密码的 DTO 做字段脱敏。

## 二、高危问题

### 2.1 dangerouslySetInnerHTML 渲染原始 HTML 无消毒

| 文件 | 行号 | 数据来源 |
|------|------|----------|
| `blog-admin/src/pages/Talk/Detail.tsx` | 110 | `talk.content` (管理员创建的 HTML) |
| `blog-admin/src/pages/Talk/components/TalkContent.tsx` | 39 | `content` prop |
| `blog-web/src/components/moment/MomentItem.tsx` | 186 | `moment.content` |
| `blog-web/src/app/[locale]/moment/[key]/page.tsx` | 154 | `moment.content` |

内容通过 `@wangeditor/editor` 富文本编辑器生成后直接注入 DOM，未经过 `DOMPurify` 或 `sanitize-html` 处理。如果编辑器输出被篡改或 API 层被绕过，存储型 XSS 可执行。

**操作**:
```bash
cd blog-web && pnpm add dompurify
cd blog-admin && pnpm add dompurify
```
在渲染前调用 `DOMPurify.sanitize(htmlContent)`。

### 2.2 文件上传无扩展名校验

**文件**: `blog-service/src/main/java/com/blog/modules/file/service/FileServiceImpl.java:67-110`

YAML 配置中定义了 `security.file-upload.allowed-extensions` 和 `blocked-extensions`（如禁止 `.jsp`、`.php`、`.exe` 等），但**没有任何 Java 代码读取这些配置并执行校验**。`isValidFileName()` 方法只在测试控制器中被调用。

`WebMvcConfig` 将 `/uploads/**` 映射为静态资源直接服务，这意味着上传的可执行文件能被直接访问。

**操作**: 在 `FileServiceImpl.upload()` 方法中增加扩展名校验逻辑。

### 2.5 CSP 允许 `'unsafe-inline'` 脚本

**文件**: `blog-service/src/main/java/com/blog/infrastructure/filter/SecurityFilter.java:369`

```java
"script-src 'self' 'unsafe-inline'"
```

`'unsafe-inline'` 使 CSP 对 XSS 的防御完全失效，内联 `<script>` 标签仍可执行。

**操作**: 移除 `'unsafe-inline'`，使用 nonce 或 hash 机制处理合法的内联脚本。

## 五、其他发现

- **后端异常处理**: `GlobalExceptionHandler` 不泄露栈追踪，返回受控的用户友好消息
