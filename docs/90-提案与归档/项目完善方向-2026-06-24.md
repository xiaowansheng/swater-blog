# 项目后续完善方向

> 基于 2026-06-23 全栈安全审计结果，梳理可继续推进的完善方向。

---

## 🔴 高优先级（安全 / 稳定性）

### 1. 移除硬编码凭据

- **文件**：`blog-service/src/main/resources/application-dev.yml:15-17`
- **现状**：明文存储管理员账号密码（`admin/admin`）和邮箱
- **建议**：改为仅从环境变量注入，删除默认值

### 2. Token 存储加固

- **文件**：`blog-admin/src/utils/storage.ts:11`
- **现状**：JWT token 存储在 localStorage，XSS 可直接读取
- **建议**：改用 httpOnly cookie + CSRF token 方案，或短期先改为 sessionStorage 并缩短有效期

### 3. CSRF 生产环境检查

- **文件**：`blog-service/src/main/java/com/blog/infrastructure/filter/SecurityFilter.java:310`
- **现状**：CSRF 检查逻辑存在但被注释为 `// return false`，注释写明"在生产环境中可以启用"
- **建议**：通过配置开关控制，生产环境默认开启

### 4. SQL 注入防护正则误杀

- **文件**：`blog-service/src/main/java/com/blog/infrastructure/security/SqlInjectionProtector.java:15-39`
- **现状**：使用 `select|insert|delete|update|drop|truncate` 等正则匹配，会对包含以上英文关键字的正常文章内容（如技术博客中的 SQL 示例）产生误拦截
- **建议**：改用参数化查询白名单 + 上下文感知过滤，而非全局正则

### 5. Next.js 图片优化恢复

- **文件**：`blog-web/next.config.ts:17`
- **现状**：`images.unoptimized: true` 关闭了全部内置图片优化
- **建议**：移除该配置，对外部域名按需使用 `remotePatterns` 白名单

## 🟡 中优先级（代码质量 / 工程化）

### 6. TypeScript `any` 类型治理

- **文件**：`blog-admin/eslint.config.js:36`
- **现状**：ESLint 显式关闭了 `@typescript-eslint/no-explicit-any`，全项目约 105+ 处 `any` 类型
- **建议**：
  - 第一阶段：开启规则设为 `warn`，不影响 CI
  - 第二阶段：逐步收窄为具体 interface/type
  - 第三阶段：升级为 `error`

**高频文件**：`Article/Import.tsx`, `Config/index.tsx`, `Comment/index.tsx`, `Visitor/index.tsx`

### 7. 巨型组件拆分

| 文件 | 行数 | 拆分建议 |
|---|---|---|
| `Article/DirectoryTree.tsx` | 1276 | 提取 TreeNode、DragDrop、FormModal 子组件 |
| `Config/index.tsx` | 1257 | 按配置类型拆分为 BooleanConfig、TextConfig、ImageConfig 等 |
| `Article/Import.tsx` | 1194 | 提取 PreviewTable、ImportConfigPanel、ResultTable |
| `Visitor/index.tsx` | 796 | 提取 VisitorTable、SessionTraces、StatisticsCharts |
| `Article/Edit.tsx` | 660 | 提取 MetadataForm、ContentEditor、CoverGeneratorSection |
| `Article/Export.tsx` | 580 | 提取 ConfigPanel、PreviewTable、ResultDisplay |

### 8. 数据请求模式封装

- **现状**：30+ 页面组件中重复出现相同的 `try/catch/fetch/setLoading` 模式
- **建议**：封装一个通用的 `useFetchList` / `useFetchDetail` hook，统一处理加载态、空态、错误态

### 9. 枚举映射表去重

- **文件**：`blog-admin/src/types/enums.ts:169-275`
- **现状**：18 个几乎完全相同的 `{ color, label, value }` 映射对象
- **建议**：提取通用 `StatusMap` 工具函数，按类型生成映射

### 10. 控制台日志清理

- **高频文件**：
  - `blog-admin/src/hooks/usePageCache.ts`（9 处未受控的 `console.log`）
  - `blog-admin/src/components/common/RichTextEditor.tsx`（乱码日志：`????????????????????????`）
- **建议**：封装 `logger` 工具，按环境变量控制输出级别

### 11. blog-admin 国际化

- **现状**：所有 UI 文本硬编码为中文，无 i18n 支持
- **建议**：
  - blog-web 已有 `next-intl` 实践，可复用语言包结构
  - 使用 `react-intl` 或 `i18next` + `react-i18next`

## 🟢 低优先级（体验 / 基础设施）

### 12. 测试体系建设

| 项目 | 现状 | 建议 |
|---|---|---|
| blog-admin | 零测试 | 至少补核心流程烟雾测试（文章 CRUD、登录） |
| blog-web | 零测试 | 补关键页面的渲染测试和 API mock 测试 |
| blog-service | 仅 8 个测试类 | 补 Service 层单测、Repository 集成测试、SecurityFilter 测试 |

### 13. 前端错误追踪

- **文件**：`blog-admin/src/components/common/ErrorBoundary.tsx:24`
- **现状**：`componentDidCatch` 仅 `console.error`，无上报
- **建议**：接入 Sentry 或自建错误收集端点

### 14. 分布式追踪

- **现状**：后端无 trace-id 跨服务传播，前后端无关联 ID
- **建议**：引入 Micrometer Tracing / OpenTelemetry，前端请求携带 `x-trace-id`

### 15. 结构化日志

- **文件**：`blog-service/src/main/resources/application-dev.yml:158-159`
- **现状**：纯文本日志模式，无 JSON 格式
- **建议**：配置 Logstash JSON encoder，统一携带 request-id

### 16. Docker 镜像固定

- **现状**：Dockerfile 使用浮动标签（`node:20-alpine`、`gradle:8.5-jdk21-jammy`、`nginx:alpine`）
- **建议**：固定为 SHA256 digest，确保可复现构建

### 17. Vite 构建优化

- **文件**：`blog-admin/vite.config.ts`
- **现状**：无代码分割配置
- **建议**：配置 `rollupOptions.output.manualChunks`，将 `antd`、`echarts`、`vditor` 分 chunk

### 18. API 错误码标准化

- **文件**：`blog-service/src/main/java/com/blog/shared/Result.java`
- **现状**：业务异常可携带自定义错误码但无标准枚举定义
- **建议**：定义 `ErrorCode` 枚举，前端按错误码做差异化处理

### 19. CSP 安全头部

- **文件**：`blog-admin/nginx.conf:79`
- **现状**：使用已废弃的 `X-XSS-Protection` 头部
- **建议**：替换为 Content-Security-Policy，同时添加 Referrer-Policy、Permissions-Policy

### 20. Redis 缓存去重

- **文件**：`blog-service/src/main/java/com/blog/bootstrap/config/CacheConfig.java:89-136`
- **现状**：`articles` 和 `article:list` 实际缓存相同数据，浪费 Redis 内存
- **建议**：统一缓存 key 命名规范，去重

### 21. 速率限制默认开启

- **文件**：`blog-service/src/main/resources/application-dev.yml:211`
- **现状**：开发环境 `rate-limit.enabled: false`
- **建议**：设置合理的默认值（如 window=60s, limit=100），按接口差异化配置

### 22. 测试调试页面移除

- **文件**：`blog-admin/src/pages/TestCache.tsx`
- **现状**：开发调试页面残留在生产路由中
- **建议**：移除或改为仅在 dev 模式下可访问

### 23. API 请求双通道统一

- **文件**：`blog-admin/src/api/article.ts:388-423`
- **现状**：`downloadExport` 使用原生 `fetch`，其他请求使用 axios，走不同拦截器链
- **建议**：统一使用 axios（配置 `responseType: 'blob'`）

### 24. 代码注释与 JSDoc

- **现状**：大部分 React 组件和 hooks 无 JSDoc 注释
- **高频文件**：`useArticleAutoSave.ts` (478 行仅稀疏注释)、`MarkdownEditor.tsx`
- **建议**：至少对导出 API 补 JSDoc
