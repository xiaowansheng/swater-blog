## 🔴 高优先级（安全 / 稳定性）

### 1. 移除硬编码凭据

- **文件**：`blog-service/src/main/resources/application-dev.yml:15-17`
- **现状**：明文存储管理员账号密码（`admin/admin`）和邮箱
- **建议**：改为仅从环境变量注入，删除默认值

### 2. Token 存储加固

- **文件**：`blog-admin/src/utils/storage.ts:11`
- **现状**：JWT token 存储在 localStorage，XSS 可直接读取
- **建议**：改用 httpOnly cookie + CSRF token 方案，或短期先改为 sessionStorage 并缩短有效期

### 3. CSRF 防护形同虚设

- **文件**：`blog-service/src/main/java/com/blog/infrastructure/filter/SecurityFilter.java:296-298, 310`
- **现状**：双重缺陷使 CSRF 检查完全失效——① line 296-298 在请求**无 Referer 头时直接放行**（注释写"可能是API调用"），攻击者只要不带 Referer 即可绕过；② line 310 的拦截 `return false` 被注释，注释写明"在生产环境中可以启用"
- **建议**：优先修复无 Referer 放行逻辑（改用 SameSite Cookie 或 Token 方案校验，而非依赖 Referer），再通过配置开关启用 line 310 的拦截

### 4. SQL 注入防护正则误杀

- **文件**：`blog-service/src/main/java/com/blog/infrastructure/security/SqlInjectionProtector.java:15-39`
- **现状**：使用 `select|insert|delete|update|drop` 等正则匹配，会对包含以上英文关键字的正常文章内容（如技术博客中的 SQL 示例）产生误拦截；其中 `system|exec|shell|cmd|eval`（line 38）误杀尤其隐蔽——这些是常见英文单词，任何英文文章都可能被拦
- **建议**：改用参数化查询白名单 + 上下文感知过滤，而非全局正则

### 5. Next.js 图片优化恢复

- **文件**：`blog-web/next.config.ts:15-28`
- **现状**：两个问题——① `images.unoptimized: true`（line 17）关闭了全部内置图片优化；② `remotePatterns` 已配置但 `hostname: "**"`（line 26）通配所有 https 域名，等于无白名单限制
- **建议**：移除 `unoptimized` 配置；将 `hostname` 收窄到实际使用的图床/COS 域名

## 落地记录：Phase 1 + Phase 4（2026-06-24 实施）

本次实施覆盖 Phase 1（安全闭环）与 Phase 4（基础设施），共完成 #1、#3、#5、#16、#17、#19 六项。

### ⚠️ 启动须知（运维必读）

**dev 环境启动前必须设置管理员环境变量**，否则 `blog-service` 启动会 fail-fast：

```bash
export BLOG_ADMIN_USERNAME=admin
export BLOG_ADMIN_PASSWORD=your_strong_password   # 必填
export BLOG_ADMIN_EMAIL=admin@example.com          # 必填
```

或写入项目根 `.env`（参考 `.env.example`）。历史 `admin/admin` 明文凭据已从 `application-dev.yml` 移除。

### 改动清单

#### Phase 1 — 安全闭环

**#1 移除硬编码 admin/admin 凭据**
- `application-dev.yml`：`username/password/email` 全部改为 `${BLOG_ADMIN_*:}` 无默认值
- `DataInitializer.java`：去掉 username/email 的 `@Value` 默认值，`validateBootstrapConfig()` 对三者均 fail-fast
- `docker-compose.yml`：blog-service 注入 `BLOG_ADMIN_*` 环境变量（可覆盖 docker profile 默认值）
- `.env.example`：新增管理员账号段，标注 dev 必填
- 测试：`DataInitializerTest` 补 username/email 缺失分支；`BootstrapProfileConfigTest` 改为校验 dev 不再硬编码

**#3 CSRF 防护：配置开关 + 收紧 Referer 逻辑**
- `application.yml`（base）：新增 `security.csrf.enabled: false`（保守默认）
- `application-docker.yml`：`security.csrf.enabled: true`（生产开启）
- `SecurityFilter.validateReferer()` 重写：
  - 新增 `csrfEnabled` 开关，关闭时不校验（兼容本地开发/无头 API）
  - **修复「无 Referer 一律放行」绕过缺陷**：已认证写请求（带 `Authorization` 或 JSON body）必须携带同源 Referer/Origin，否则拒绝
  - 新增 `isSameOrigin()` / `stripDefaultPort()` 规范化同源判断，启用历史注释的 `return false`
  - 校验改为优先用更可靠的 `Origin` 头，其次 `Referer`
- 注：CSRF 为纯逻辑改动，依赖 Spring 上下文，建议补集成测试（属 Phase 3 范围，本次未覆盖）

#### Phase 4 — 基础设施

**#5 Next.js 图片优化恢复 + remotePatterns 收紧**
- `blog-web/next.config.ts`：移除 `unoptimized: true`，恢复内置优化
- 新增 `buildImageRemotePatterns()`：从 `NEXT_PUBLIC_UPLOAD_RESOURCE_PREFIX` 解析主机名构建白名单，废弃危险的 `hostname: "**"` 通配
- 注意：生产环境该变量为相对路径 `/uploads`（同源），无需跨域白名单；`picsum.photos`（演示占位图）未入白名单，生产部署前应移除该占位数据

**#16 Docker 镜像固定为 digest**（8 个 Dockerfile）
所有基础镜像固定为 SHA256 digest，沿用项目既有 pin 模式（mysql/redis/acme-companion 已是 digest）：
| 镜像 | 位置 |
|---|---|
| `node:20-alpine` | blog-admin、blog-web（builder + runtime） |
| `nginx:alpine` | blog-admin runtime、docker/nginx |
| `eclipse-temurin:21-jre-jammy` | blog-service runtime |
| `gradle:8.5-jdk21-jammy` | blog-service builder |
| `nginxproxy/nginx-proxy:1.6` | docker/nginx/Dockerfile.proxy |
| `elasticsearch:8.11.0` | docker/elasticsearch |
| `rabbitmq:3-management-alpine` | docker/rabbitmq |
> digest 在标签变动后需重新校验；本次 digest 通过 Docker Hub registry API 解析（2026-06-24）。

**#17 Vite manualChunks 分包**
- `blog-admin/vite.config.ts`：新增 `build.rollupOptions.output.manualChunks`
- 拆出 5 个 vendor chunk：`react-vendor`(346kB)、`antd-vendor`(1.4MB)、`echarts-vendor`(1.1MB)、`editor-vendor`(1.1MB)、`pdf-vendor`(561kB)
- 构建验证通过（`pnpm build` 成功）。echarts/vditor 等库本身较大，单 vendor 内进一步拆分收益有限，维持现状

**#19 CSP / 安全头部 + nginx add_header 继承修复**
- 新建 `blog-admin/security-headers.conf` 片段，集中管理安全头
- 移除废弃的 `X-XSS-Protection`，新增 `Content-Security-Policy`（宽松起步）、`Permissions-Policy`，收紧 `Referrer-Policy` 为 `strict-origin-when-cross-origin`
- **修复 nginx add_header 继承陷阱**：各 location 显式 `include /etc/nginx/security-headers.conf;`，避免静态资源/API location 因自身 `add_header` 覆盖丢失安全头
- `blog-admin/Dockerfile`：新增 `COPY security-headers.conf /etc/nginx/security-headers.conf`
- `nginx -t` 语法校验通过；CSP 为「宽松起步」，生产前建议用 Report-URI 收集违规后逐步收紧（见片段注释）
